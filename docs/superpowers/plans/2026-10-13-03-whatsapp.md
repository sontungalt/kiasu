# Kiasu: Plan 03, WhatsApp (client, window, outbox, webhook, task queue)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**This is plan 03 of 07.** It runs in parallel with plans 01, 02, 04, 05 and 06 (tasks 1–4), after plan 00, in its own worktree.

**Goal:** Build everything WhatsApp: a Graph API client that splits long text and sends templates, the 24h-window check, an outbox that queues messages behind a template when the window is closed and flushes them in order when it reopens, the signed Meta webhook that dedupes and enqueues my messages, and the Cloud Tasks (and local inline) queue that hands them to plan 05.

**Architecture:** Five small modules under `src/whatsapp/`, each built by a factory that takes its dependencies explicitly, so tests use `MemoryStore`, `FakeClock`, a fake `fetch`, a fake WhatsApp client or a fake Cloud Tasks client, and never touch the network. The webhook is a `RouteRegistrar` with its own raw-body parser, scoped to it, because the HMAC covers Meta's exact bytes. Cross-instance safety (duplicate webhooks, concurrent flushes, template spam) uses the atomic `store.processed.claim`. No new store fields are needed.

**Tech Stack:** Node 24, TypeScript (NodeNext ESM, `.js` import suffixes), Fastify 5, vitest 5, `@google-cloud/tasks` 7 (already in `package.json` from plan 00), `node:crypto`, global `fetch`/`Response`.

**Spec:** `docs/superpowers/specs/2026-10-13-kiasu-design.md` (WhatsApp: §3, §4, §8.1, §9 security, §10, §13). **Contracts:** `docs/superpowers/plans/2026-10-13-00-foundation.md` (`src/types.ts`, `src/ports.ts`, `src/store/types.ts`, `src/config.ts`, `src/server.ts`, `test/helpers/deps.ts`). These are treated as already implemented and are **not modified** by this plan.

**Contract change:** none. **Spec deviation (template wording only):** the `heads_up` body in spec §8.1 (`⚠️ Heads up: {{1}}`) ends with a variable, and Meta rejects that ("Leading or trailing parameters not allowed"). Task 7 submits `⚠️ Heads up: {{1}}` + `\n\nTap Details to see the full message.` It still has one parameter, so no code or type changes.

## Global Constraints

- Node 24 + TypeScript, ESM with `module`/`moduleResolution: NodeNext`. Relative imports end in `.js`.
- **Only messages from `MY_WHATSAPP_NUMBER` (digits only) are processed.** All others are dropped and logged (spec §9).
- Every stored timestamp is a UTC ISO string from `toISOString()`. Webhook timestamps (unix seconds) are converted at the boundary.
- Never log message text or email bodies. Log message ids, types, counts and error codes.
- WhatsApp templates: category *Utility*, language `en`, names exactly `brief_ready` and `heads_up` (`TemplateName`).
- Graph API URL: `https://graph.facebook.com/{WA_GRAPH_VERSION}/{WA_PHONE_NUMBER_ID}/messages`. The recipient is always `MY_WHATSAPP_NUMBER`.
- Webhook auth: `X-Hub-Signature-256` = `sha256=` + hex HMAC-SHA256 of the **raw** body with `WA_APP_SECRET`. GET handshake: `hub.verify_token` must equal `WA_VERIFY_TOKEN`.
- Duplicate deliveries: a `processed/{key}` claim first, and every handler is idempotent (spec §10).
- A failed WhatsApp send stays `pending` in the outbox and is retried on the next tick, and the error code is logged (spec §10).
- Do not modify `src/types.ts`, `src/ports.ts`, `src/store/types.ts`, `src/lib/clock.ts`, `src/server.ts`, `test/helpers/deps.ts`.
- Tests make no network calls. Every task ends with `npm test` and `npm run typecheck` passing.

## Review Focus

1. **Meta delivers the same message twice or out of order** (it retries for up to 7 days, and batches aren't ordered). Expected: one task per message id, and `lastInboundAt` never moves backwards. *Pinned by:* Task 5 tests `Meta delivering the same message twice enqueues it once` and `out-of-order delivery never moves lastInboundAt backwards`.
2. **The window closes between our check and the send** (our `lastInboundAt` says open, Meta answers 131047). Expected: the message stays pending, a template goes out, and nothing is marked failed. *Pinned by:* Task 3 test `window closes between the check and the send (131047)`.
3. **A flush races a concurrent deliver or another flush** (the tick and a button tap at once, possibly on two Cloud Run instances). Expected: every message is sent exactly once and in creation order. *Pinned by:* Task 3 tests `two concurrent flushes (two instances) send each message exactly once` and `a deliver racing a flush in the same process keeps order and sends once`.
4. **The signature is checked on a re-serialised body instead of the raw bytes** (Meta escapes unicode as `é`, which `JSON.stringify` doesn't reproduce). Expected: verification uses the raw bytes, and a message with accents or emoji is accepted. *Pinned by:* Task 4 test `a re-serialised body does not verify` and Task 5 test `verifies against the raw bytes (escaped unicode body)`.
5. **A reply with emoji or multi-byte characters near the 4096 limit.** Expected: every chunk is at most 4096 UTF-16 units, and no emoji is cut in half. *Pinned by:* Task 2 tests `never splits an emoji's surrogate pair` and `emoji-dense text near the limit`.

Also covered by tests, not in the top five: a status-only webhook, and a stranger messaging the bot number (Task 5).

```ts
import { HOUR_MS } from "../lib/clock.js";

/** Meta's customer-service window: free-form messages are allowed for 24h after my last inbound message. */
export const WINDOW_MS = 24 * HOUR_MS;
/** Treat the window as closed 5 minutes early, so a send that starts just before expiry can't land just after it. */
export const WINDOW_SAFETY_MS = 5 * 60_000;

export function isWindowOpen(lastInboundAt: string | null, now: Date): boolean {
  if (!lastInboundAt) return false;
  const last = Date.parse(lastInboundAt);
  if (Number.isNaN(last)) return false;
  return now.getTime() - last < WINDOW_MS - WINDOW_SAFETY_MS;
}
```

```ts
/**
 * WhatsApp's text body limit. Measured in UTF-16 code units (String.length), which is never
 * smaller than the code-point count, so a chunk that fits here also fits Meta's limit.
 */
export const WA_TEXT_LIMIT = 4096;

const SEPARATORS = ["\n\n", "\n", " "];

function isHighSurrogate(code: number): boolean {
  return code >= 0xd800 && code <= 0xdbff;
}

/** Where to cut `window` (the first limit+1 chars of the remaining text). Returns a value in [1, limit]. */
function cutPoint(window: string, limit: number): number {
  // Prefer the latest paragraph break, then line break, then space, in the second half of the window.
  const min = Math.floor(limit / 2);
  for (const sep of SEPARATORS) {
    const i = window.lastIndexOf(sep);
    if (i >= min) return i;
  }
  // Otherwise accept a break anywhere.
  for (const sep of SEPARATORS) {
    const i = window.lastIndexOf(sep);
    if (i > 0) return i;
  }
  // No whitespace at all: hard cut, but never between the two halves of a surrogate pair (emoji).
  let cut = limit;
  if (isHighSurrogate(window.charCodeAt(cut - 1))) cut -= 1;
  return Math.max(1, cut);
}

/** Splits text into chunks of at most `limit` UTF-16 units, on paragraph/line/word boundaries where possible. */
export function splitText(text: string, limit: number = WA_TEXT_LIMIT): string[] {
  if (text.length <= limit) return [text];
  const chunks: string[] = [];
  let rest = text;
  while (rest.length > limit) {
    const cut = cutPoint(rest.slice(0, limit + 1), limit);
    const head = rest.slice(0, cut).trimEnd();
    if (head) chunks.push(head);
    rest = rest.slice(cut).trimStart();
  }
  if (rest) chunks.push(rest);
  return chunks;
}
```

```ts
/** A failed Graph API call. `code` is Meta's error code (null for network/parse failures). */
export class WhatsAppError extends Error {
  readonly status: number;
  readonly code: number | null;
  constructor(status: number, code: number | null, message: string) {
    super(message);
    this.name = "WhatsAppError";
    this.status = status;
    this.code = code;
  }
}

/** Graph API error codes we act on or log. See docs/whatsapp-templates.md for sources. */
export const WA_ERROR = {
  REENGAGEMENT: 131047, // more than 24h since the recipient last replied: send a template instead
  UNDELIVERABLE: 131026,
  PAIR_RATE_LIMIT: 131056, // too many messages to the same recipient in a short time
  THROUGHPUT_LIMIT: 130429,
  TOKEN_EXPIRED: 190,
  TEMPLATE_PARAM_COUNT: 132000,
  TEMPLATE_MISSING: 132001,
  TEMPLATE_PARAM_FORMAT: 132018,
} as const;

/** True when Meta says the 24h customer-service window is closed. */
export function isWindowClosedError(err: unknown): boolean {
  return err instanceof WhatsAppError && err.code === WA_ERROR.REENGAGEMENT;
}

const TEMPLATE_PARAM_MAX = 300;

/**
 * Template parameters may not contain newlines, tabs or 5+ consecutive spaces (error 132018),
 * and may not be empty. Collapse whitespace, substitute "-" for empty, cap the length.
 */
export function sanitiseTemplateParam(value: string): string {
  const flat = value.replace(/\s+/g, " ").trim();
  if (!flat) return "-";
  const codePoints = Array.from(flat);
  return codePoints.length > TEMPLATE_PARAM_MAX ? `${codePoints.slice(0, TEMPLATE_PARAM_MAX - 1).join("")}…` : flat;
}

interface GraphResponse {
  messages?: Array<{ id?: unknown }>;
  error?: { message?: unknown; code?: unknown; error_data?: { details?: unknown } };
}

export function createWhatsAppClient(config: Config, fetchImpl: typeof fetch = fetch): WhatsAppClient {
  const url = `https://graph.facebook.com/${config.WA_GRAPH_VERSION}/${config.WA_PHONE_NUMBER_ID}/messages`;

  async function post(payload: Record<string, unknown>): Promise<string> {
    let res: Response;
    try {
      res = await fetchImpl(url, {
        method: "POST",
        headers: { authorization: `Bearer ${config.WA_ACCESS_TOKEN}`, "content-type": "application/json" },
        body: JSON.stringify({
          messaging_product: "whatsapp",
          recipient_type: "individual",
          to: config.MY_WHATSAPP_NUMBER,
          ...payload,
        }),
        signal: AbortSignal.timeout(15_000),
      });
    } catch (err) {
      throw new WhatsAppError(0, null, `WhatsApp network error: ${err instanceof Error ? err.message : String(err)}`);
    }
    const body = (await res.json().catch(() => null)) as GraphResponse | null;
    if (!res.ok) {
      const e = body?.error;
      const code = typeof e?.code === "number" ? e.code : null;
      const detail = typeof e?.error_data?.details === "string" ? e.error_data.details
        : typeof e?.message === "string" ? e.message : "no error body";
      // The code goes into the message too, because the logger only serialises message/name/stack.
      throw new WhatsAppError(res.status, code, `WhatsApp API error ${code ?? "?"} (HTTP ${res.status}): ${detail}`);
    }
    const id = body?.messages?.[0]?.id;
    if (typeof id !== "string") throw new WhatsAppError(res.status, null, "WhatsApp API response had no message id");
    return id;
  }

  return {
    async sendText(text: string) {
      if (!text.trim()) throw new WhatsAppError(0, null, "Refusing to send an empty WhatsApp message");
      let messageId = "";
      for (const chunk of splitText(text)) {
        messageId = await post({ type: "text", text: { body: chunk, preview_url: false } });
      }
      return { messageId };
    },

    async sendTemplate(template: TemplateRef) {
      // Quick-reply buttons have no parameters, so only the body component is sent.
      const components = template.params.length > 0
        ? [{ type: "body", parameters: template.params.map((p) => ({ type: "text", text: sanitiseTemplateParam(p) })) }]
        : [];
      const messageId = await post({
        type: "template",
        template: { name: template.name, language: { code: "en" }, components },
      });
      return { messageId };
    },
  };
}
```

Behaviour:
- `deliver(msg)` **always stores the message as pending first**, then runs the same send loop as `flush`. Older pending messages therefore go out first, and a `deliver` can never overtake them. It returns `"sent"` if this message went out, otherwise `"queued"`.
  - Window closed (by `lastInboundAt`), or Meta answers 131047 → send `msg.template`, unless a template already went out in the current 10-minute bucket (`processed.claim("wa:tpl:<bucket>")`, which is atomic across instances). All pending messages flush together when I reply.
  - The template send fails → flag the message (`lastError` starts with `template:`). `flush()` retries it in a later bucket while the window stays closed.
- The send loop (`flush`) sends pending messages oldest-first and stops at the first problem:
  - A text send fails → `attempts++` and `lastError` are recorded, and after 5 attempts the message is marked `failed`. 131047 never counts toward `failed`.
  - Before each send it claims `wa:out:<id>:<attempts>:<10-min bucket>`. If another flush (on any instance) holds that claim, it stops ("busy"). A claim left by a crashed instance expires with its bucket.
- `deliver` and `flush` are serialised within one process (promise chain). `createdAt` is strictly increasing per process, so messages created in the same millisecond keep their order.

```ts
import type { Deps, OutboundMessage, Outbox } from "../ports.js";
import type { OutboxMessage, TemplateRef } from "../types.js";
import { isWindowClosedError } from "./client.js";
import { isWindowOpen } from "./window.js";

/** A message whose free-text send has failed this many times is marked "failed". */
export const MAX_SEND_ATTEMPTS = 5;
/** At most one "you have messages waiting" template per 10-minute clock bucket. */
export const TEMPLATE_GAP_MS = 10 * 60_000;
/** A send claim is valid for its 10-minute bucket, so a claim left by a crashed instance expires. */
export const SEND_CLAIM_MS = 10 * 60_000;
/** Prefix of `lastError` when the notification template for a queued message failed (flush() retries it). */
export const TEMPLATE_FAILED = "template:";

type FlushStop = "drained" | "window_closed" | "reengagement" | "send_failed" | "busy";
type NotifyResult = "sent" | "suppressed" | "failed";

const errorText = (err: unknown) => (err instanceof Error ? err.message : String(err));

export function createOutbox(deps: Pick<Deps, "clock" | "log" | "store" | "whatsapp">): Outbox {
  const { clock, log, store, whatsapp } = deps;
  let tail: Promise<unknown> = Promise.resolve();
  let lastCreatedMs = 0;

  /** Runs `fn` after every earlier deliver/flush in this process has finished. */
  function serial<T>(fn: () => Promise<T>): Promise<T> {
    const run = tail.then(fn, fn);
    tail = run.catch(() => undefined);
    return run;
  }

  /** Strictly increasing createdAt, so messages created in the same millisecond keep their order. */
  function nextCreatedAt(): string {
    lastCreatedMs = Math.max(clock.now().getTime(), lastCreatedMs + 1);
    return new Date(lastCreatedMs).toISOString();
  }

  async function windowOpen(): Promise<boolean> {
    const s = await store.state.get("whatsapp");
    return isWindowOpen(s?.lastInboundAt ?? null, clock.now());
  }

  /** Atomic, cross-instance: only one flusher may send attempt N of a message within a 10-minute bucket. */
  async function claimSend(m: OutboxMessage): Promise<boolean> {
    const now = clock.now();
    const bucket = Math.floor(now.getTime() / SEND_CLAIM_MS);
    return store.processed.claim(`wa:out:${m.id}:${m.attempts}:${bucket}`, now.toISOString());
  }

  /** Sends pending messages oldest-first while the window is open. Stops at the first problem. */
  async function sendPending(): Promise<{ sent: Set<string>; stop: FlushStop }> {
    const sent = new Set<string>();
    if (!(await windowOpen())) return { sent, stop: "window_closed" };
    for (const m of await store.outbox.listPending()) {
      if (!(await claimSend(m))) {
        log.warn("outbox: message is being sent by another flush", { outboxId: m.id });
        return { sent, stop: "busy" };
      }
      try {
        await whatsapp.sendText(m.text);
      } catch (err) {
        const attempts = m.attempts + 1;
        const reengagement = isWindowClosedError(err);
        const failed = !reengagement && attempts >= MAX_SEND_ATTEMPTS;
        await store.outbox.update(m.id, { attempts, lastError: errorText(err), status: failed ? "failed" : "pending" });
        log.error(failed ? "outbox: giving up on message" : "outbox: send failed", { outboxId: m.id, kind: m.kind, attempts, err });
        return { sent, stop: reengagement ? "reengagement" : "send_failed" };
      }
      await store.outbox.update(m.id, { status: "sent", sentAt: clock.now().toISOString(), lastError: null });
      sent.add(m.id);
    }
    return { sent, stop: "drained" };
  }

  /** Sends `template` unless one already went out in this bucket. On failure, flags `outboxId` for retry. */
  async function notify(template: TemplateRef, outboxId: string): Promise<NotifyResult> {
    const now = clock.now();
    const bucket = Math.floor(now.getTime() / TEMPLATE_GAP_MS);
    if (!(await store.processed.claim(`wa:tpl:${bucket}`, now.toISOString()))) {
      log.info("outbox: template suppressed, one was sent recently", { outboxId });
      return "suppressed";
    }
    try {
      await whatsapp.sendTemplate(template);
      log.info("outbox: template sent", { outboxId, template: template.name });
      return "sent";
    } catch (err) {
      log.error("outbox: template send failed", { outboxId, template: template.name, err });
      await store.outbox.update(outboxId, { lastError: `${TEMPLATE_FAILED} ${errorText(err)}` });
      return "failed";
    }
  }

  /** Window closed: if a pending message's notification template failed earlier, try once more. */
  async function retryFailedTemplate(): Promise<void> {
    const flagged = (await store.outbox.listPending()).filter((m) => m.lastError?.startsWith(TEMPLATE_FAILED));
    const latest = flagged.at(-1);
    if (!latest?.template) return;
    if ((await notify(latest.template, latest.id)) === "sent") {
      for (const m of flagged) await store.outbox.update(m.id, { lastError: null });
    }
  }

  /** Meta reported the window closed mid-flush: tell me with the newest pending message's template. */
  async function notifyLatestPending(): Promise<void> {
    const latest = (await store.outbox.listPending()).filter((m) => m.template).at(-1);
    if (latest?.template) await notify(latest.template, latest.id);
  }

  return {
    deliver: (msg: OutboundMessage) =>
      serial(async () => {
        // Always queue first, then flush: older pending messages go out before this one.
        const rec = await store.outbox.create({
          kind: msg.kind, text: msg.text, template: msg.template,
          status: "pending", attempts: 0, lastError: null, createdAt: nextCreatedAt(), sentAt: null,
        });
        const { sent, stop } = await sendPending();
        if (sent.has(rec.id)) return "sent";
        if (stop === "window_closed" || stop === "reengagement") await notify(msg.template, rec.id);
        return "queued";
      }),

    flush: () =>
      serial(async () => {
        const { sent, stop } = await sendPending();
        if (stop === "reengagement") await notifyLatestPending();
        else if (stop === "window_closed") await retryFailedTemplate();
        return sent.size;
      }),
  };
}
```

```ts
import { createHash, createHmac, timingSafeEqual } from "node:crypto";
import type { InboundMessage } from "../types.js";

/** The subset of a Cloud API webhook message we read. Fields are optional because the payload is external. */
export interface WaRawMessage {
  id: string;
  from: string;
  type: string;
  timestamp?: string;
  text?: { body?: unknown };
  button?: { text?: unknown; payload?: unknown };
  interactive?: {
    type?: unknown;
    button_reply?: { id?: unknown; title?: unknown };
    list_reply?: { id?: unknown; title?: unknown; description?: unknown };
  };
  context?: { from?: unknown; id?: unknown };
}

export interface WaRawStatus {
  id: string;
  status: string;
  recipient_id?: string;
  errors?: Array<{ code?: unknown; title?: unknown }>;
}

export interface WebhookContents {
  messages: WaRawMessage[];
  statuses: WaRawStatus[];
}

/** Message types that aren't something I "said": no agent call, no window update. */
export const IGNORED_TYPES: ReadonlySet<string> = new Set(["reaction", "system"]);

const isObj = (v: unknown): v is Record<string, unknown> => typeof v === "object" && v !== null;
const arr = (v: unknown): unknown[] => (Array.isArray(v) ? v : []);
const isStr = (v: unknown): v is string => typeof v === "string" && v.length > 0;

/**
 * Verifies Meta's `X-Hub-Signature-256: sha256=<hex>` header: an HMAC-SHA256 of the exact raw
 * request bytes, keyed with the app secret. Never pass a re-serialised body.
 */
export function verifyMetaSignature(rawBody: Buffer, header: string | string[] | undefined, appSecret: string): boolean {
  if (typeof header !== "string" || !header.startsWith("sha256=")) return false;
  const hex = header.slice("sha256=".length);
  if (!/^[0-9a-fA-F]{64}$/.test(hex)) return false;
  const expected = createHmac("sha256", appSecret).update(rawBody).digest();
  const given = Buffer.from(hex, "hex");
  return given.length === expected.length && timingSafeEqual(given, expected);
}

/** Constant-time string comparison of any lengths (hash both sides first). */
export function safeEqual(a: string, b: string): boolean {
  const ha = createHash("sha256").update(a).digest();
  const hb = createHash("sha256").update(b).digest();
  return timingSafeEqual(ha, hb);
}

/** Collects every entry[].changes[].value.messages[] and .statuses[] item that has the fields we need. */
export function extractWebhook(payload: unknown): WebhookContents {
  const out: WebhookContents = { messages: [], statuses: [] };
  if (!isObj(payload)) return out;
  for (const entry of arr(payload.entry)) {
    if (!isObj(entry)) continue;
    for (const change of arr(entry.changes)) {
      if (!isObj(change) || !isObj(change.value)) continue;
      for (const m of arr(change.value.messages)) {
        if (isObj(m) && isStr(m.id) && isStr(m.from) && isStr(m.type)) out.messages.push(m as unknown as WaRawMessage);
      }
      for (const s of arr(change.value.statuses)) {
        if (isObj(s) && isStr(s.id) && isStr(s.status)) out.statuses.push(s as unknown as WaRawStatus);
      }
    }
  }
  return out;
}

/** Webhook timestamps are unix seconds as a string ("1749416383"). Falls back to `now` if unusable. */
export function unixToIso(ts: string | undefined, now: Date): string {
  const n = Number(ts);
  return Number.isFinite(n) && n > 0 ? new Date(n * 1000).toISOString() : now.toISOString();
}

export function toInboundMessage(m: WaRawMessage, now: Date): InboundMessage {
  const base = {
    id: m.id,
    from: m.from,
    timestamp: unixToIso(m.timestamp, now),
    contextMessageId: isStr(m.context?.id) ? m.context.id : null,
  };
  if (m.type === "text" && typeof m.text?.body === "string") return { ...base, type: "text", text: m.text.body };
  // Template quick-reply tap.
  if (m.type === "button" && typeof m.button?.text === "string") return { ...base, type: "button", text: m.button.text };
  // Interactive reply buttons / list rows (not sent by v1, but mapped the same way).
  if (m.type === "interactive") {
    const title = m.interactive?.button_reply?.title ?? m.interactive?.list_reply?.title;
    if (typeof title === "string") return { ...base, type: "button", text: title };
  }
  return { ...base, type: "unsupported", text: null };
}
```

```ts
import type { Deps } from "../ports.js";
import type { RouteRegistrar } from "../server.js";
import {
  extractWebhook, IGNORED_TYPES, safeEqual, toInboundMessage, verifyMetaSignature, type WaRawMessage,
} from "./inbound.js";

/** Raises state.whatsapp.lastInboundAt to `atIso` (never lowers it: deliveries can arrive out of order). */
async function bumpLastInbound(deps: Deps, atIso: string): Promise<void> {
  const cur = await deps.store.state.get("whatsapp");
  if (cur?.lastInboundAt && cur.lastInboundAt >= atIso) return;
  await deps.store.state.set("whatsapp", { ...(cur ?? {}), lastInboundAt: atIso });
}

async function processMessage(deps: Deps, m: WaRawMessage): Promise<void> {
  const now = deps.clock.now();
  if (m.from !== deps.config.MY_WHATSAPP_NUMBER) {
    deps.log.warn("whatsapp: dropped message from unknown sender", { messageId: m.id, fromSuffix: m.from.slice(-4), type: m.type });
    return;
  }
  if (!(await deps.store.processed.claim(`wa:${m.id}`, now.toISOString()))) {
    deps.log.info("whatsapp: duplicate delivery skipped", { messageId: m.id });
    return;
  }
  if (IGNORED_TYPES.has(m.type)) {
    deps.log.info("whatsapp: ignored message type", { messageId: m.id, type: m.type });
    return;
  }
  const msg = toInboundMessage(m, now);
  await bumpLastInbound(deps, msg.timestamp);
  await deps.tasks.enqueueInbound(msg);
  deps.log.info("whatsapp: message enqueued", { messageId: msg.id, type: msg.type });
}

export const registerWhatsAppRoutes: RouteRegistrar = async (app, deps) => {
  // This scope only: keep the body as raw bytes, because the signature covers the exact bytes Meta sent.
  app.removeAllContentTypeParsers();
  app.addContentTypeParser("*", { parseAs: "buffer" }, (_request, body, done) => done(null, body));

  app.get("/webhooks/whatsapp", async (request, reply) => {
    const q = request.query as Record<string, unknown>;
    const token = q["hub.verify_token"];
    const challenge = q["hub.challenge"];
    if (q["hub.mode"] === "subscribe" && typeof token === "string" && typeof challenge === "string"
      && safeEqual(token, deps.config.WA_VERIFY_TOKEN)) {
      return reply.code(200).type("text/plain").send(challenge);
    }
    deps.log.warn("whatsapp: verification handshake rejected");
    return reply.code(403).send({ error: "forbidden" });
  });

  app.post("/webhooks/whatsapp", async (request, reply) => {
    const raw = Buffer.isBuffer(request.body) ? request.body : Buffer.alloc(0);
    if (!verifyMetaSignature(raw, request.headers["x-hub-signature-256"], deps.config.WA_APP_SECRET)) {
      deps.log.warn("whatsapp: bad webhook signature");
      return reply.code(401).send({ error: "bad signature" });
    }

    let payload: unknown;
    try {
      payload = JSON.parse(raw.toString("utf8"));
    } catch {
      deps.log.warn("whatsapp: signed webhook body is not JSON");
      return reply.code(200).send({ ok: true });
    }

    const { messages, statuses } = extractWebhook(payload);
    for (const s of statuses) {
      if (s.status === "failed") {
        deps.log.warn("whatsapp: outbound message failed", { messageId: s.id, codes: (s.errors ?? []).map((e) => e.code) });
      }
    }
    // Sequential, so messages in one batch are enqueued in the order Meta sent them.
    for (const m of messages) {
      try {
        await processMessage(deps, m);
      } catch (err) {
        deps.log.error("whatsapp: failed to process inbound message", { messageId: m.id, err });
      }
    }
    // Always 200 once the signature is valid: Meta retries anything else for up to 7 days.
    return reply.code(200).send({ ok: true });
  });
};
```

```ts
import { createHash } from "node:crypto";
import { CloudTasksClient } from "@google-cloud/tasks";
import type { Config } from "../config.js";
import { silentLogger, type Logger } from "../lib/log.js";
import type { TaskQueue } from "../ports.js";
import type { InboundMessage } from "../types.js";

/** Route served by plan 05; the OIDC audience must equal PUBLIC_BASE_URL + this path. */
export const HANDLE_MESSAGE_PATH = "/tasks/handle-message";

const GRPC_ALREADY_EXISTS = 6;

/**
 * Task ids allow only [A-Za-z0-9_-] (max 500). A sha256 hex of the WhatsApp message id is valid,
 * stable per message (so a re-enqueue dedupes), and non-sequential, which Google recommends.
 */
export function taskIdFor(messageId: string): string {
  return createHash("sha256").update(messageId).digest("hex");
}

export function createCloudTaskQueue(config: Config, client?: Pick<CloudTasksClient, "createTask">): TaskQueue {
  const url = `${config.PUBLIC_BASE_URL.replace(/\/$/, "")}${HANDLE_MESSAGE_PATH}`;
  let tasks = client;
  return {
    async enqueueInbound(msg: InboundMessage): Promise<void> {
      tasks ??= new CloudTasksClient();
      try {
        await tasks.createTask({
          parent: config.TASKS_QUEUE,
          task: {
            name: `${config.TASKS_QUEUE}/tasks/${taskIdFor(msg.id)}`,
            httpRequest: {
              httpMethod: "POST",
              url,
              headers: { "Content-Type": "application/json" },
              body: Buffer.from(JSON.stringify(msg)).toString("base64"),
              oidcToken: { serviceAccountEmail: config.INVOKER_SERVICE_ACCOUNT, audience: url },
            },
          },
        });
      } catch (err) {
        // Same message enqueued before (Meta retry, or a duplicate that slipped past the claim): fine.
        if ((err as { code?: unknown }).code === GRPC_ALREADY_EXISTS) return;
        throw err;
      }
    },
  };
}

/** Local dev: runs the handler in the background so the webhook can still answer immediately. */
export function createInlineTaskQueue(
  handle: (msg: InboundMessage) => Promise<void>,
  log: Logger = silentLogger,
): TaskQueue {
  return {
    async enqueueInbound(msg: InboundMessage): Promise<void> {
      setImmediate(() => {
        Promise.resolve()
          .then(() => handle(msg))
          .catch((err: unknown) => log.error("inline task failed", { messageId: msg.id, err }));
      });
    },
  };
}
```

````markdown
## Error codes the code handles

| Code | Meaning | Handling |
|---|---|---|
| 131047 | More than 24h since my last message (re-engagement) | The outbox treats the window as closed: the message stays pending and a template is sent |
| 131026 | Message undeliverable | The send fails: retried by `flush()`, marked `failed` after 5 attempts |
| 131056 / 130429 | Pair rate limit / throughput limit | Same as above (retried on the next tick) |
| 132000 / 132001 / 132018 | Template parameter count / missing template or language / bad parameter format | Logged. The pending message is flagged and the template is retried at most once per 10 minutes until I message the bot |
| 190 | Access token expired | Logged. Replace `WA_ACCESS_TOKEN` (use a permanent System User token) |

A 131047 can also arrive later as a `failed` status webhook instead of in the send response. The webhook logs failed statuses with their error codes, but it doesn't requeue the message (see the Review Focus in plan 03).
````

**Known limits (accepted for v1, not tested):**
- A 131047 that arrives **only** asynchronously, as a `failed` status webhook after a 200 send, is logged but not requeued. The 5-minute safety margin, plus `lastInboundAt` coming from Meta's own message timestamps, make this rare.
- If `enqueueInbound` throws after the claim, that one message is lost (Meta won't retry a 200). It's logged with its id, and I can just resend.
- A long text split into chunks that fails mid-way resends the earlier chunks on retry.
- The `lastInboundAt` update is read-modify-write. Two concurrent webhooks could store the older of two timestamps, which only makes the window look shorter, so it's safe.
- A `deliver` on instance B while instance A is flushing returns `"queued"`. The message goes out on the next tick's flush, at most 5 minutes later.
